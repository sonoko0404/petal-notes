## 性能实测

环境：Windows 11 家庭版 x64，系统版本 10.0.26200；AMD Ryzen 9 5900HX，8 核 / 16 逻辑处理器，物理内存约 15.4 GiB。Release、自包含 win-x64、ReadyToRun 发布，.NET SDK 10.0.400。测试期间电脑仍运行其他日常应用。

| 场景 | 指标 | 结果 |
| --- | --- | --- |
| 发布版启动 | 进程启动至启动诊断回调 | 1.62 秒 |
| 日常 10 张便签，4 分钟 | 空闲平均 CPU，排除首个启动样本 | 0.080% |
| 日常 10 张便签，4 分钟 | 工作集 | 204.3–208.4 MiB |

| 20 张便签，30 分钟 | 句柄数范围 | 1320–1393 |

CPU 按 16 个逻辑处理器归一化，接近任务管理器的整机百分比口径。工作集包含共享运行时页面，私有内存单列，两者不能互相替代。**原计划 150 MB 的工作集目标未达到**。启动测量不是独立的首帧计时，UI 调度延迟也不是拖动帧率；不作零卡顿保证。

持续观察时，20 张便签保持打开并取消置顶，以免遮挡其他工作；没有运行中的番茄钟。观察包含此前打开设置、五种主题、六种字体及窗口渲染所加载的资源。工作集和私有内存未出现持续增长，也未出现无响应或崩溃。句柄数从首个样本的 1342 增加到最后的 1392，后半段有上升趋势，原因尚未定位；需要更长周期及资源类型分析，不能据此宣称完全没有资源泄漏。

长文本检查：24000 characters, layout 582.9 ms。20 窗口批量修改正文、位置、尺寸并处理待办：Batch layout 1060.2 ms。两项均验证了修改后的保存和恢复，批量耗时不等同于单次按键延迟。

核心测试覆盖中文／表情符号、待办、提醒及计时状态往返；保存快照隔离、并发写入顺序、原子替换、损坏主文件恢复、备份保护、未知版本拒绝覆盖、写入失败恢复，以及计时暂停、补报、长休息和无重复推进。

窗口集成测试直接运行 WPF 窗口，覆盖提醒表单无效时间和过去日期的拒绝、指定时间和每日提醒保存、稍后提醒与完成按钮、默认字体只作用于新便签、缺失字体回退、时长校验、番茄钟关闭窗口后继续运行、搜索和回收站恢复、20 窗口同时编辑移动缩放及全部隐藏／恢复。

Computer Use 另行核对了实际键盘输入、Ctrl+A、Enter 新增待办、勾选删除线、折叠展开、标题条拖动、主题与楷体切换、字体下拉框、隐藏后管理页恢复、重启内容恢复、单实例唤起和正常退出。此类测试使用隔离数据，并仅为工具枚举窗口而开启便签任务栏可见性；普通运行默认隐藏任务栏条目。
