# 花瓣清单：桌面小组件 — 产品需求规格

**英文名：** Petal Checklist Widget  
**状态：** 已确认基线  
**确认日期：** 2026-09-23  
**首发平台：** macOS 14+  
**后续平台：** iPhone、iPad  

## 1. 产品定义

花瓣清单是一款以 macOS 桌面 Widget 为核心的轻量个人任务产品。用户打开电脑即可看见当天少量重要事项，无需打开 App 就能直接勾选完成。

产品不提供独立悬浮便签窗口。桌面呈现完全由 WidgetKit Widget 承担；轻量承载 App 负责新增、编辑、搜索、归档、导入导出、同步状态和设置。

### 1.1 核心用户

希望桌面清爽、每天只管理少量事项的 Mac 学生和个人知识工作者。典型用户拥有 1–10 张活跃卡片，不想维护复杂的 GTD、项目或知识库体系。

### 1.2 核心承诺

> 打开电脑就看到今天要做什么，不打开 App 也能直接勾选。

### 1.3 产品原则

1. **可见优先：** 最重要的事项应直接出现在桌面。
2. **行动优先：** 勾选待办不需要打开 App。
3. **轻量优先：** 不演化成完整项目管理器或文档编辑器。
4. **离线优先：** 没有网络或 iCloud 时仍能创建、编辑和完成任务。
5. **隐私优先：** 不自建账号、不上传内容、不接第三方行为分析。
6. **数据可带走：** 支持机器可恢复备份和人类可读导出。

## 2. MVP 用户旅程

### 2.1 第一次使用

1. 用户启动 App。
2. App 自动创建不可直接删除的“收集箱”和一张示例卡片。
3. 引导用户通过三步把 Petal Widget 添加到桌面。
4. 用户为 Widget 选择卡片、主题和字体。
5. 用户直接在 Widget 中勾选示例待办。

### 2.2 日常快速记录

1. 用户按 `⌥⌘N`，或点击某个 Widget 的“＋”。
2. 小型快速新增面板在热启动时 300ms 内进入可输入状态。
3. 默认创建待办；`Shift + Enter` 换行，`Enter` 保存，`Esc` 取消。
4. 从 Widget 打开时加入该 Widget 对应卡片；从全局快捷键打开时加入“收集箱”。
5. 保存成功后面板关闭，焦点返回原来的 App；失败时保留输入并展示原因。

### 2.3 完成任务

1. 用户在 Widget 中点击待办 Toggle。
2. UI 立即显示完成反馈，并在通常 1 秒内稳定为持久化后的正确状态。
3. 完成项移动到卡片末尾，当天继续显示。
4. 次日完成项从 Widget 隐藏，但仍保留在 App 的已完成区域。

### 2.4 编辑与整理

1. 点击 Widget 中的文字，App 深链打开对应卡片。
2. 用户新增、编辑、删除、排序内容行，或在普通文字与待办之间转换。
3. 用户可搜索标题、普通文字和待办。
4. 完成的整张卡片可归档；误删卡片进入 30 天回收站。

### 2.5 提醒

1. 用户为某个待办设置单次或每日提醒。
2. 第一次设置提醒时，App 解释用途并申请通知权限。
3. 通知提供“完成”“延后 5 分钟”“打开卡片”。
4. 通知默认静音；横幅和通知中心行为由 macOS 设置控制。

## 3. 功能需求

### 3.1 卡片与内容

- **FR-001** App 必须自动创建一个“收集箱”。用户可重命名，但删除前必须先指定另一张默认卡片。
- **FR-002** 用户可以创建、重命名、归档、恢复和删除卡片。
- **FR-003** 卡片状态必须包括活跃、归档和回收站。
- **FR-004** 回收站中的卡片必须在删除 30 天后永久清理。
- **FR-005** 卡片内容必须由有序内容行组成。
- **FR-006** 每行必须能够在普通文字和待办两种类型间转换。
- **FR-007** 用户必须能够拖动排序内容行。
- **FR-008** 新增内容默认创建为待办。
- **FR-009** 一次性待办的完成状态必须保留到用户删除卡片或内容行。
- **FR-010** 每日待办只保存最近完成日期与当前连续完成次数，不创建无限增长的每日历史。
- **FR-011** App 不设置卡片数量或内容行数量的人为上限。

### 3.2 Widget

- **FR-020** 首版必须提供中号和大号 macOS Widget。
- **FR-021** 一个 Widget 必须对应一张卡片。
- **FR-022** 同一张卡片必须允许配置到多个 Widget。
- **FR-023** Widget 配置必须允许选择卡片、主题、字体和透明感变体。
- **FR-024** Widget 配置、尺寸和桌面布局必须保持设备本地，不通过 iCloud 强制复制。
- **FR-025** Widget 必须优先展示按手动顺序排列的未完成项。
- **FR-026** 内容超出容量时，Widget 必须显示“还有 N 项”，点击后打开对应卡片。
- **FR-027** Widget 必须使用 Toggle 直接完成或取消完成待办。
- **FR-028** 点击文字必须深链打开对应卡片编辑页。
- **FR-029** 点击“＋”必须打开绑定到该卡片的快速新增面板。
- **FR-030** Widget 不得提供文字输入、滚动长列表、删除、排序或主题编辑。
- **FR-031** 卡片被归档或删除后，关联 Widget 必须显示状态说明和“选择其他卡片”入口。
- **FR-032** Widget 数据暂时不可用时必须展示最后缓存内容；只有过期或同步失败时显示轻量状态提示。

### 3.3 承载 App

- **FR-040** App 必须是标准 Dock App，不常驻菜单栏。
- **FR-041** 主窗口必须使用单窗口三栏结构：范围侧边栏、卡片列表、卡片编辑器。
- **FR-042** 侧边栏必须包括收集箱、全部卡片、归档、回收站和设置。
- **FR-043** 搜索必须覆盖标题、普通文字和待办，并能返回归档及回收站结果。
- **FR-044** 关闭 App 窗口不得影响 Widget 显示和交互。
- **FR-045** 用户必须能通过可配置的全局快捷键打开快速新增面板；默认快捷键为 `⌥⌘N`。
- **FR-046** 快捷键冲突时必须提示用户修改或关闭快捷键。
- **FR-047** App 必须显示“已同步、正在同步、离线、同步失败”四类简洁状态。

### 3.4 完成语义

- **FR-050** 完成项必须移动到卡片末尾。
- **FR-051** 完成当天，完成项必须继续在 Widget 中以完成样式显示。
- **FR-052** 本地日期进入下一天后，完成项必须从 Widget 隐藏。
- **FR-053** 取消完成必须恢复为未完成项，并回到其手动排序位置。
- **FR-054** 每日待办到达新的本地日期后必须恢复为未完成。

### 3.5 提醒与通知

- **FR-060** 提醒必须绑定单个待办，普通文字行不能设置提醒。
- **FR-061** 提醒必须支持单次和每日两种规则。
- **FR-062** 单次提醒必须保存绝对时间点。
- **FR-063** 每日提醒必须按设备当前所在地的当地时间触发。
- **FR-064** 通知必须支持完成、延后 5 分钟和打开卡片。
- **FR-065** 通知声音必须默认关闭，并可在设置中开启。
- **FR-066** 用户拒绝通知权限后，App 必须保留提醒配置、提示其不会收到通知，并提供系统设置入口。
- **FR-067** 提醒必须在所有登录同一 iCloud 且允许通知的设备上调度。
- **FR-068** 在一台设备完成待办后，其他设备必须在同步到状态后取消对应待处理通知。

### 3.6 本地数据与 iCloud

- **FR-070** 所有编辑必须先写入本地持久化存储，再异步同步。
- **FR-071** 无网络、未登录 iCloud 或用户关闭同步时，App 的本地功能必须完整可用。
- **FR-072** 首版只使用用户的私人 iCloud 数据库，不提供 Petal 账号。
- **FR-073** 首版不得支持多人共享、协作邀请或公开链接。
- **FR-074** 不同设备修改不同内容行时必须合并保留。
- **FR-075** 同一内容行发生并发冲突时必须采用最后修改版本，并创建可恢复的冲突副本。
- **FR-076** 冲突副本必须保留 30 天，并只向用户提示一次。
- **FR-077** 删除、归档和恢复必须同步到用户的其他设备。
- **FR-078** 用户必须能够关闭 iCloud 同步，关闭后保留完整本地副本。

### 3.7 导入、导出与删除

- **FR-080** App 必须能够导入 Windows 版 `notes.json`。
- **FR-081** 导入必须保留标题、正文段落、待办、完成状态、提醒和最接近的主题。
- **FR-082** 导入必须忽略窗口位置、置顶、隐藏、折叠和番茄钟。
- **FR-083** 导入前必须生成备份；重复导入不得创建重复卡片。
- **FR-084** App 必须支持完整 JSON 导出与恢复。
- **FR-085** App 必须支持 Markdown 人类可读导出。
- **FR-086** 导出不得包含 Widget 布局等设备本地状态。
- **FR-087** 设置必须提供“删除全部 Petal 数据”，经二次确认后清除本机与私人 iCloud 数据。

### 3.8 主题与本地化

- **FR-090** 必须提供奶油、薄荷、樱花、天空和极简五套主题。
- **FR-091** 每套主题可以提供有限的背景色、系统字体和透明感变体。
- **FR-092** 只能使用 macOS 内置字体和系统字体设计，不打包第三方字体。
- **FR-093** 必须适配浅色、深色和 macOS Widget 的系统渲染模式。
- **FR-094** 首发必须完整支持简体中文和英文。

### 3.9 Onboarding、帮助与反馈

- **FR-100** 首次启动必须创建包含三步操作的示例卡片。
- **FR-101** 首次启动必须说明如何把 Widget 加到桌面；App 不得声称能自动添加 Widget。
- **FR-102** App 必须提供内置帮助页、反馈邮箱和隐私政策链接。
- **FR-103** 反馈邮件可以附带 App 版本和系统版本，但不得附带卡片内容。

## 4. 非功能需求

### 4.1 性能

- **NFR-001** 热启动快速新增面板必须在 300ms 内进入可输入状态。
- **NFR-002** App 冷启动必须在 2 秒内进入可编辑状态。
- **NFR-003** Widget 勾选必须立即产生视觉反馈，并通常在 1 秒内稳定为持久化状态。
- **NFR-004** 搜索、排序和同步队列必须在 500 张卡片、5,000 行内容下保持可用。

### 4.2 可靠性

- **NFR-010** 发布候选版必须没有已知数据丢失问题或可复现崩溃。
- **NFR-011** 写入失败时不得丢弃用户尚未保存的输入。
- **NFR-012** 断网、进程终止、系统重启和同步冲突后必须能够恢复到最近一次成功本地写入。
- **NFR-013** Schema 升级必须可迁移并拒绝以旧代码覆盖未知新版本数据。

### 4.3 隐私与安全

- **NFR-020** 不得接入第三方用户行为分析 SDK。
- **NFR-021** 不得将卡片内容发送到开发者服务器。
- **NFR-022** 必须启用 App Sandbox，并通过 App Group 在 App 与 Widget Extension 之间共享本地数据。
- **NFR-023** 首版依赖 macOS 登录保护和私人 iCloud，不实现自定义密码锁或二次加密。
- **NFR-024** 隐私政策必须在 App 内和 App Store 元数据中可访问。

### 4.4 无障碍

- **NFR-030** App 与 Widget 必须支持 VoiceOver。
- **NFR-031** App 的核心操作必须能够只用键盘完成。
- **NFR-032** 必须提供清晰焦点状态、足够颜色对比度，并尊重减少动态效果设置。
- **NFR-033** Widget 中每个待办必须朗读内容、完成状态和可执行动作。

### 4.5 兼容性

- **NFR-040** 最低部署目标为 macOS 14。
- **NFR-041** 必须同时构建和验证 arm64 与 x86_64。
- **NFR-042** 后续 iPhone/iPad 客户端必须复用核心模型、WidgetKit 视图和 App Intent，而不改变现有云端 Schema 语义。

## 5. 明确排除的首版范围

- 独立悬浮便签窗口。
- Widget 内直接输入文字或滚动长列表。
- 图片、附件、扫描、手写和富文本。
- 文件夹、标签、优先级、截止日期和项目看板。
- 多人协作和公开分享链接。
- 番茄钟。
- 自建账号、认证服务或业务服务器。
- Android 或新的 Windows 客户端。
- 广告、订阅、主题商店和付费墙。
- 第三方用户行为分析。

## 6. 发布与验证

### 6.1 商业与商店

- 首版免费，无广告、无付费墙。
- App Store 分类为“效率”。
- 目标年龄分级为 4+。
- 中文商店名使用“花瓣清单：桌面小组件”；英文使用“Petal Checklist Widget”。最终可用性以 App Store Connect 创建记录结果为准。
- 本地原型完成核心 Widget 闭环后加入 Apple Developer Program，并创建正式 Bundle ID、iCloud 容器和 App Store 记录。

### 6.2 测试人群

- 邀请 20–30 名符合目标画像的用户参与四周 TestFlight 测试。
- 每周一次简短回访，不用开发团队成员代替真实目标用户。

### 6.3 成功指标

以首批 20 名完成入组的测试者为基准：

- 至少 14 人成功添加 Widget。
- 至少 8 人在第四周仍持续使用。
- 至少 5 人表示失去产品会明显不方便。

### 6.4 范围削减顺序

若 8–10 周不足，依次延后：

1. Windows 数据导入。
2. 每日重复提醒。
3. 主题自定义变体。

不得削减 Widget 勾选闭环、轻量编辑器、本地可靠保存、iCloud 数据模型、基本单次提醒、无障碍或数据安全。

## 7. 发布验收

发布前必须完成：

1. 中号、大号 Widget 的添加、配置、缓存和交互验证。
2. 本地离线编辑、重新联网和同步验证。
3. 两台设备同时编辑不同内容行与同一内容行的冲突验证。
4. 单次提醒、每日提醒、延后、完成和跨时区验证。
5. Windows 导入、JSON 恢复、Markdown 导出与删除全部数据验证。
6. 中文、英文、VoiceOver、键盘和减少动态效果验证。
7. Apple Silicon 与 Intel Mac 验证。
8. 500 张卡片、5,000 行内容的压力验证。
9. 隐私政策、帮助、支持邮箱、商店截图和审核说明检查。

## 8. 官方平台约束

- Widget 交互采用 `Button`、`Toggle` 与 App Intent；文本编辑保留在承载 App。  
  <https://developer.apple.com/documentation/widgetkit/adding-interactivity-to-widgets-and-live-activities>
- Widget 是承载 App 的 Extension，安装后用户需要先启动承载 App，才能在 Widget Gallery 中使用。  
  <https://developer.apple.com/documentation/widgetkit/creating-a-widget-extension>
- App Store Connect、TestFlight、CloudKit 生产能力和正式分发需要 Apple Developer Program。  
  <https://developer.apple.com/support/compare-memberships/>
