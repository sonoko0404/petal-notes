# App Review notes — draft, not submitted

Petal Checklist Widget is a macOS 14+ checklist whose primary daily surface is a medium or large desktop Widget. The standard Dock app has one lightweight window for creating and editing cards, searching, settings, import/export, and viewing sync state. There are no floating sticky-note windows. The app contains no login, in-app purchase, subscription, ad, or hidden paywall. No reviewer account or credentials are required. The first launch creates an Inbox and an example card; this is local sample content generated by the app, not a claim that an external test account or seeded CloudKit data exists.

To review the core flow on a properly signed and provisioned build:

1. Launch the containing app once. Follow its three-step onboarding; the app cannot add a Widget automatically.
2. Control-click the macOS desktop, choose Edit Widgets, find Petal, and add a medium or large Widget. Edit its configuration to select the example card, theme, font, and appearance.
3. Click a to-do circle in the Widget to complete it. Click card text to open the card in the app. Click the plus button to quick add to that card, or press Option–Command–N to quick add to Inbox.
4. In the app, edit a line, search for a card, and open Settings to inspect import, JSON backup/restore, Markdown export, and sync controls. JSON restore replaces the dataset, so use disposable review content.
5. To inspect reminders, save an enabled reminder. The app requests notification permission at the first enabled reminder; it does not request permission on first launch. Notification sound is off by default. Exercise delivery and actions only on a signed build with the required permissions.

All edits persist locally before optional iCloud replication. iCloud sync uses the person's private CloudKit database when enabled and available; local operation works without iCloud. Production CloudKit schema and two-Mac behavior remain blocked until separately verified. No developer-operated service receives card content. Feedback is disabled until the owner configures an approved support mailbox. Privacy and help text remain available in-app offline; proposed web URLs are unpublished and unverified until the owner enables Pages.
